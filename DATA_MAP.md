Update this file in the same PR as any schema change that adds/removes a personal-data field — it must always match
`supabase/migrations` exactly, not lag behind it.

## Notes

- **No advertising identifier, no ATT-gated data, no cross-app tracking** is collected anywhere in this table —
  intentional, not an omission (brief §18, §29).
- **No free-text user content is logged into `app_events`** — `properties` is restricted to primitive values keyed
  by a closed set of event names (see `packages/domain/src/models/analytics.ts`).
- **Breed** is stored only as a free-text/optional field for the user's own reference and is never used by the plan
  engine or any behavior-prediction logic (brief §4: "Do not suggest that breed alone determines behavior").
- Whenever a new SDK is integrated (crash reporting, etc.), a new row is added here — and to PRIVACY.md and the
  store questionnaires — **before** it ships, not retroactively.
