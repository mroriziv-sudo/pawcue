# Clicker sound design

The clicker is the product's signature interaction and its acquisition wedge: it is the first thing the app does,
before any account, permission or paywall. The sound is therefore a product surface, not an asset detail.

**No final candidate has been chosen.** Three ship in the development build behind a developer-only selector so
they can be compared on real hardware. `DEFAULT_CLICK_SOUND_ID` is a placeholder, not a recommendation.

## Origin

All three are synthesised from scratch by [`tools/audio/generate-click-sounds.mjs`](../../tools/audio/generate-click-sounds.mjs).

There is no sampled or third-party source material anywhere in the pipeline — the output is original by
construction, so no licensing question arises. The generator is deterministic (seeded PRNG), so the committed
WAVs can be regenerated byte-for-byte:

```bash
pnpm --filter @pawcue/mobile run audio:generate
```

## How they are built

A physical box clicker is a metal tongue snapped through a bistable position, striking a plastic housing.
Acoustically that is three things, and the generator models each:

1. **The snap** — bandpassed noise under a very fast exponential decay (1.6–3.0ms).
2. **The body** — three damped sine modes between 1.2kHz and 5.6kHz, all decaying within ~10ms.
3. **The settle** — a quieter second transient 2–3ms later, as the tongue comes to rest against the housing.

Point 3 is what separates a clicker from a snare hit or a UI blip, and it is why each candidate renders a
secondary transient rather than a single envelope.

Two constraints shaped the tuning more than anything else:

- **Modal decays are kept short and capped in frequency.** Long, high, ringing modes are precisely what makes a
  synthetic click read as _metallic_ or _digital_, both of which the brief rules out.
- **The lowpass is cascaded, not single-pole.** The first pass used one pole (-6dB/octave) and measured a
  spectral centroid above 6kHz — audibly hissy rather than mechanical. Real box clickers sit nearer 2.5–3.5kHz.
  Cascading sections to -12/-18dB/octave removed the "tss" without dulling the transient.

## The candidates

|                   | A — Classic                                             | B — Soft Premium                            | C — Crisp                           |
| ----------------- | ------------------------------------------------------- | ------------------------------------------- | ----------------------------------- |
| Intent            | Closest to a physical clicker. Neutral, dry, realistic. | Warmer, less fatiguing over a long session. | Sharper, cuts through a noisy park. |
| Duration          | 45.0 ms                                                 | 55.0 ms                                     | 38.0 ms                             |
| Peak              | -5.03 dBFS                                              | -5.80 dBFS                                  | -1.00 dBFS                          |
| RMS               | -20.03 dBFS                                             | -20.03 dBFS                                 | -20.03 dBFS                         |
| Spectral centroid | ~3.4 kHz                                                | ~2.2 kHz                                    | ~5.2 kHz                            |
| Attack to 90%     | 1.81 ms                                                 | 0.65 ms                                     | 0.48 ms                             |
| Audible until     | 20.4 ms                                                 | 29.4 ms                                     | 12.2 ms                             |
| Noise centre / Q  | 2600 Hz / 1.8                                           | 1750 Hz / 1.6                               | 3600 Hz / 2.0                       |
| Lowpass           | 5600 Hz × 3 poles                                       | 4200 Hz × 3 poles                           | 7000 Hz × 2 poles                   |
| File              | 4364 bytes                                              | 5324 bytes                                  | 3692 bytes                          |

All three: **mono, 16-bit PCM, 48kHz, zero clipped samples.**

48kHz rather than 44.1kHz because it is the native rate of both the Android audio path and current iOS hardware,
so the OS mixer never resamples — and resampling a 40ms transient is exactly where a crisp attack gets smeared.

### Why loudness is matched by RMS, not peak

Normalising each file to the same _peak_ would be misleading: C has a much higher peak-to-average ratio than B,
so peak-matching would leave it audibly quieter. The generator matches RMS across the three and then applies a
single shared gain that puts the loudest peak at -1 dBFS. A listening test then compares character, not volume,
which is the entire point of shipping three.

## Enforced specification

[`apps/mobile/__tests__/click-sound-assets.test.ts`](../../apps/mobile/__tests__/click-sound-assets.test.ts)
decodes the committed WAVs and asserts every requirement, so a regeneration cannot quietly ship something worse:

- mono / 16-bit / 48kHz, uncompressed PCM
- duration within 35–70ms
- **no leading silence** — the first millisecond is above 50% of peak
- full level reached within 5ms
- **no clipping** — peak below 0.95 FS, zero samples at the rail
- clearly audible — peak above 0.45 FS
- **no ringing tail** — the final millisecond is below -60dB relative to peak, and the last sample is exactly zero
- **dry** — everything above -26dB of peak finishes within 30ms
- loudness matched across candidates to within 1.5dB RMS
- each candidate measurably brighter than the last (soft < classic < crisp)

## The developer-only selector

Settings → _Clicker sound (dev only)_, gated behind `__DEV__`.

It is deliberately **untranslated**: translating it would imply it is a user-facing feature, which it is not. It
routes through the same preload/playback engine the product uses, so a preview cannot sound different from the
clicker screen.

[`apps/mobile/__tests__/dev-only-ui.test.tsx`](../../apps/mobile/__tests__/dev-only-ui.test.tsx) renders Settings
with `__DEV__` forced to `false` and asserts the selector is absent — a `__DEV__` check is otherwise invisible in
every test run that never flips it.

**Before release:** either remove the selector or get explicit approval to keep it. Tracked in RELEASE_CHECKLIST.md.

## Choosing

The decision belongs to the product owner and should be made **on a physical device**, not the Simulator: the
Simulator routes audio through the host's output, which says nothing about how a 40ms transient behaves on a
phone speaker at arm's length in a park. The relevant questions are which candidate stays comfortable after a
hundred repetitions, and which is still unambiguous outdoors.
